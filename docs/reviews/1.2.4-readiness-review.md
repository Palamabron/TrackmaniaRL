# TrackmaniaRL 1.2.4 readiness review

The release supplies runnable first-party configurations and integration coverage
for the public workflows below. Support means the documented software contracts
are implemented and tested. It does not promise a particular lap time.

## Completion evidence

| Surface | Verified workflow |
| --- | --- |
| SAC, REDQ, TQC and stable discrete SAC | Generated configurations, first-party models, collection, updates, checkpoint loading, resume and Trackmania evaluator |
| PPO and camera vision | Telemetry and vision RunSpecs, bounded actions, fixed rollouts, GAE, update, resume, episode resets, CNN composition and evaluation |
| Graph recovery | Eighteen causal incident archives spanning progress, severity and direction bins, source checkpoint provenance, gated samples, held-out selection, policy checkpoint reload and evaluation. Source weights remain unchanged |
| DAgger | Public command with real teacher and BC student, student and teacher action routing, episode resets, archive metadata and subsequent BC training with disjoint episode splits |
| Synthetic recovery | Public command output consumed by BC training. Invalid configuration fails without replacing the existing archive |
| Trajectory optimization | Public command, persisted schedule reload, environment cleanup and explicit failure when the requested time target is unmet. Unit tests separately cover candidate acceptance and rejection |
| Distribution | Declared extras match the archive validator. Installed-wheel smoke validates all seven generated Trackmania configurations without importing checkout code |

Integration fixtures replace the live environment connection where a game is
necessary. Archive formats, geometry, models, learners, command dispatch,
selection and checkpoint codecs are real library implementations. Image tests
also cover preprocessing, frame-source conversion and resource cleanup.

## Corrections

The release validator now accepts the declared `vision` extra. PPO rejects an
incompatible sampler or undersized rollout capacity and preserves terminal flags
when preparing time-limit batches. Startup failures close training resources.
DAgger closes its logger even when environment cleanup raises.
Run resolution closes partially constructed logger stacks on configuration errors.
Project creation validates package names before filesystem writes and rejects
names that would shadow the library. Both have regression coverage.
The distributed protocol requires episode identity and complete control-loop
observability fields. Payloads from other protocol shapes are rejected.

Documentation identifies public algorithms and data workflows consistently and
describes interfaces, data movement, parameters, failure conditions and checkpoint
lifecycles. Current guides target library version 1.2.4.

## Deliberate scope boundaries

PPO is local on-policy training, not distributed off-policy collection. SAC-family
replay supports single-step samples, not recurrent sequence training. Camera
policies use RGB input while telemetry drives reward, progress and termination.

Recovery fine-tuning trains the incident-gated adapter, not arbitrary models.
Its selected policy-only checkpoint supports evaluation and compatible weight
initialization, not exact interrupted fine-tuning resume.

Optional dependencies and abstract extension hooks are intentional interfaces.
Generated map paths and UIDs must refer to the user's own assets.
`trackmaniarl.experiments` remains an implementation namespace for supported graph
components and existing checkpoints. Repository-only benchmark files preserve
research provenance and are not default policies.

Version 1.2.4 is a strict current-schema release. It provides no compatibility
aliases or loading path for previous RunSpec, checkpoint, replay or
distributed payload shapes. Existing runs must remain with the library version
that created them. Start a new 1.2.4 run with current configuration and data.

## Live smoke verification on 2026-09-09

An already configured Windows Trackmania host passed the real-map preflight with
33-field telemetry, session protocol 2 and matching geometry. Both telemetry PPO
and image PPO collected 32 real transitions, completed two updates, wrote
checkpoints and resumed from the first checkpoint to the same transition/update
budget. These used short 16-step rollouts, one optimization epoch and CPU inference.

A separate 20-step image/control probe applied straight acceleration, observed
7.65 m of vehicle movement, changing RGB frames and finite `(4, 84, 84)` features.
The requested decision interval was 50 ms. Observed race-clock steps were
50–70 ms and desktop capture took 15.5–32.2 ms per frame on this host. The game
viewport was kept unobstructed. Controllers were released after each test.

This verifies live connectivity, capture, control, short updates and continuation,
not learned driving quality or full-lap reliability. There is no new multi-lap
performance claim. Local screenshots, checkpoints and host-specific configs remain
ignored and are not published. Atomic camera/telemetry synchronization is not
provided, and another host must measure its own timing.
