# TrackmaniaRL 1.2.0 public-library release review

Review date: 2026-09-08. Scope: the supplied working tree, portable Python
library, documentation/media, distributables and history reachable from HEAD.
The initial review did not publish or rewrite history. The remediation record at
the end documents the later reviewed merge and authorized history rewrite.

## Verdict: READY WITH DOCUMENTED LIMITATIONS

The portable code and packaging gates pass as recorded below. The maintainer
approved publication with the residual history and external-integration limits
documented in this review. Ordinary clones of
the rewritten repository no longer receive the exposed legacy password, personal
home paths or private serialized artifacts. GitHub's read-only pull-request refs
and two external forks can still retain the old objects, so full server-side
expungement remains incomplete. The local environment
contained the matching legacy password during the initial audit; it has now been
rotated locally. Its use by external services is not known. Rotate it anywhere
else it remains active or has been reused. Sanitizing the
current files or rewriting branches does not revoke a credential or remove copies
held in forks, cached pages or read-only pull-request refs.

A CPU-wheel dependency audit additionally reports a setuptools advisory whose
fixed version conflicts with PyTorch's runtime requirement. The isolated package
builder already uses the fixed version. The narrow runtime-only acceptance and
isolated-build mitigation are now recorded in SECURITY.md.

## Privacy and security evidence

- Scanned all **8,361 reachable blobs from 974 commits** for concrete home paths
  and common credential signatures; also checked commit-message signatures.
- Compared three local credential candidates in memory against every reachable
  blob without printing values. The legacy password matched five versions of:
  `tmrl/env_init/resources/config_imgs.json`,
  `tmrl/env_init/resources/config_lidars.json`, and
  `docs/config_tqcgrab_1actor_recommended.json`.
  The current W&B/Gemini values did not match these historical blobs.
- Reachable commits contain 30 distinct author/committer identities. These were
  counted without reproducing names or addresses. Intentional project attribution
  in LICENSE/NOTICE/package metadata was preserved; it is distinct from accidental
  machine/account paths. No claim is made that Git history is anonymous.
- Broad email matching in binary PNG bytes and private-IP-looking package version
  strings in the lockfile were false positives. Published PNG metadata has no
  EXIF/account fields; one diagram carries ordinary DPI metadata. GIFs carry
  playback/looping metadata. The wheel has no ZIP comment and the locally built
  sdist has empty owner/group names and no global PAX metadata.
- `.env` and local artifacts remain ignored. Additional `.env.*`, key-file,
  NumPy-dataset and assistant-state protections were added. `.env-example` keeps
  empty credentials and is included in the source archive.
- Torch loading rejects an executable pickle regression fixture before its
  marker can execute, and removes decompression staging files. YAML safe parsing
  does not make component resolution safe for untrusted configuration: imports
  and constructors execute Python. These trust boundaries remain explicit.
- Archive screening covers packaged bytes, including embedded metadata and docs;
  it is not an exhaustive secret detector, semantic dataset audit or full forensic
  image analysis. Raw recordings, replay and model artifacts are not distributed.
- Final source screening covered **501 tracked or publishable untracked files**
  with no current signature or local-credential matches. The **262-member wheel**
  and **549-member source archive** passed the privacy guard and a separate
  in-memory comparison against local credential values: no matching members.
  The only intentionally retained identifying metadata is reviewed project and
  license attribution; this does not clear the historical disclosures above.

Detailed redacted findings and raw local gate logs are in the ignored
`artifacts/release-review-1.2.0/` directory. Logs may contain local runtime paths;
do not publish that evidence directory without separate redaction.

`smoke_installed.py` installs a temporary generated extension and is intended only
for a disposable environment. It asserts the library import is not the checkout
and runs CLI subprocesses outside it. No system site packages are inherited.
The dependency audit command returns nonzero for the advisory described below.

The dependency advisory is `PYSEC-2026-3447`: Unicode normalization can bypass
MANIFEST exclusions in setuptools before 83, particularly on macOS filesystems.
The isolated CPU environment resolves setuptools 81 because torch 2.11.0+cpu
requires `setuptools<82`. Project and generated-project isolated build systems
already pin setuptools 83.0.0. Do not build release archives using an unisolated
Torch runtime environment; do not force-install setuptools 83 contrary to Torch's
declared dependency. The raw dependency audit remains **not green**; the narrow
runtime-only acceptance and isolated-build mitigation are recorded in SECURITY.md.
No active vulnerability exploitation was
performed. The scan does not cover every optional-extra dependency combination.
